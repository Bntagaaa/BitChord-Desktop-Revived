# Desktop video engine audit

Baseline: `87ada9ada74e385a8bc168ffeca7d4b32aa43e23` on `1.9.3-phase-1`, the merge of [PR #156](https://github.com/Bntagaaa/BitChord-Desktop-Revived/pull/156). The workspace snapshot matched the fetched commit. The separate experimental branch ended at `d2468fe7`; it was inspected without merging.

## Video and resource ownership

| Consumer | Entry points | Current producer and ownership |
| --- | --- | --- |
| Expanded and fullscreen Now Playing, animated covers, Spotify Canvas and Apple Motion Artwork | `DesktopApp` → `DesktopPlayerSheet` → shared `NowPlayingScreen` → `CanvasArtworkPlayer` → `DesktopPlayerHost.CanvasVideo` | `DesktopCanvasVideo` owns a `DesktopCanvasDecoder` inside each mounted effect. Different player layouts have separate render slots. The shared player passes fit/crop, top alignment, bottom fade, presentation alpha, and a requested palette capture size. |
| Now Playing details and playlist header | `DesktopNowPlayingDetailsPanel` and `DesktopCollectionPage` → `DesktopCanvasView` | A separate effect opens a `DesktopCanvasDecoder`. The playlist path can run independently. A matching Canvas URL mounted in another slot does not reuse this decode. |
| Artist hero | Generic `DesktopArtistBanner` and `DesktopAppleArtistUi` → `DesktopContinuedArtistMotionView` | Each banner effect owns `DesktopContinuedArtistDecoder`. It selects an HLS rendition, draws with crop, and can retain the first frame for a palette. Window visibility gates this effect; hero viewport intersection is absent in the base implementation. |
| Music video | Shared `NowPlayingScreen` and `MusicVideoLayout` → `DesktopPlayerHost` → `DesktopMusicVideoSurface` | `DesktopMusicVideo` owns the process-level `DesktopVideoSession`. Surfaces count attachments per track. The session resolves video quality and signed headers, then wraps `DesktopCanvasDecoder` with looping disabled and a larger size ceiling. |
| Video-derived backgrounds | Shared `NowPlayingScreen` mesh, colors and blur, plus `DesktopNowPlayingDetailsPanel` | Shared Now Playing receives captured images from the active Canvas slot. Details reads the single-frame `DesktopCanvasBackdrop` slot by URL. The player also layers gradients, offscreen masks, blur and controls over moving pixels. |
| Mini player and PiP | `DesktopMiniPlayer`, `DesktopBackgroundPlaybackHost`, `DesktopPipHost`, `DesktopPipWindow`, `DesktopPipUi` | The mini player and PiP use still artwork. PiP owns an independent Compose window and small artwork/blur resources. There is no video surface attached to PiP in the base branch. Opening it hides the main window and continues the audio service. |

Provider and cache boundaries:

- `DesktopCanvasClient`, `DesktopCanvasSources`, `DesktopSpotifyCanvas` and Apple artist providers select metadata and URLs. `DesktopCanvasCache.fileFor` resolves clips to deterministic disk paths; HLS can bypass that disk cache. Apple artist rendition hints have a bounded in-memory cache. Artwork and Coil image caches are distinct from decoder and renderer allocations.
- Both native video decoders use JavaCPP/FFmpeg demux, codec, packet/frame, native BGRA scale buffer and `sws_scale`. Each transfers the scaled BGRA bytes to JVM memory. Their differences include HLS rendition selection, pacing and seek/timestamp support.
- Motion paths recycle three JVM arrays, but create a Skia raster image for every displayed frame. Compose retains the latest wrapper; there is no explicit consumption or release acknowledgement from the renderer. Rotation is a bound on arrays, not proof of Skia lifetime or native-memory bounds. Confirm the exact Skiko copy behavior before adopting any borrowed memory scheme.
- The music path uses a native-to-JVM copy, a new full-frame `pixels.copyOf()`, and a raster image created on painter draw. A single BGRA frame is 7.91 MiB at 1080p or 31.64 MiB at 4K. At 30 fps the array clone alone accounts for up to 237 or 949 MiB/s respectively. These are payload calculations, not measured allocation rates.
- `DesktopCanvasVideo.stableCanvasSnapshot` converts full decoded frames to ARGB and recreates an image, even though the shared player supplies `frameCapturePx`. The other motion paths snapshot a full frame on the first frame of each reopened pass. Artwork and background can share one produced frame today, but URL-only backdrop ownership lets one producer clear another's snapshot for the same URL.
- A successful FFmpeg open can occur before the coroutine reaches the cleanup handler in `DesktopCanvasVideo` and `DesktopCanvasView`. Cancellation at the IO dispatcher handoff can strand the opened decoder. In `DesktopContinuedArtistDecoder`, the codec is assigned to the owner after parameter setup/open and the options dictionary has no corresponding free, unlike `DesktopCanvasDecoder`. Blocking native IO is not coroutine-interruptible by itself.
- Motion call sites can reopen at loop boundaries when seek does not work, notably for HLS. The music session shares within one track ID, but zero attachments between layouts can restart the decoder. Source identity needs to distinguish rendition, headers, track incarnation, initial position and clock ownership. FFmpeg's probe and codec pools are native allocations outside the Java array ring.
- `Main` keeps the main window mounted when hidden. The older motion views consult window visibility; `DesktopCanvasVideo` itself only pauses on play/transition state and can open before checking it. Music visibility depends on attachment lifetime. Minimize, tray, PiP and viewport visibility require independent verification of the last active consumer.
- `DesktopPageMemoryPolicy` trims artwork/image caches at pressure and may call GC and Linux `malloc_trim`. Artist-motion disposal directly invokes the global trim. RSS includes native video, Skia, audio, allocator and driver memory. Changes in RSS alone cannot identify a leak.

## Audio and navigation boundaries

`DesktopPlaybackService` owns `DesktopPlaybackEngine`. The latter owns audio source resolution, FFmpeg audio decode, DSP, speed processing and device output through the existing audio pipeline/sinks. `DesktopBackgroundPlaybackHost` publishes the audio position, monotonic sample time, seek serial, buffering state and song to `DesktopMusicVideo`; rate is published by `DesktopPlayerHost`. Any replacement must consume these signals and discard media audio. Queue, audio sink, DSP, lossless policy and audio routing are outside video lifetime.

`DesktopWindowMode` and `Main` own native fullscreen placement, including the Windows HWND bridge. `DesktopApp` retains the Home feed and scroll state when the Now Playing overlay opens. The video surface may be rebound inside that window without reconstructing Home. Background playback and tray controls live outside the main UI's visibility.

## Previous fixes and evidence

- `21aea906` and `760f634b` introduced recycled motion buffers and retained backdrop snapshots. `ee9cb1d0` removed a process-lifetime URL/path map. `9a2e9c38` and `10962783` suspend the older motion views when hidden. `d6fc6416` and `45ee7165` preserve Home artwork and content across player overlays. Existing unit coverage includes music-video attachment and clock tests, motion buffer rotation, Home retention, window placement and memory policy.
- The [MediaMP branch checks](https://github.com/Bntagaaa/BitChord-Desktop-Revived/actions/runs/44744721371) passed Linux and Windows desktop unit/package checks. Their steps do not test a real Wayland or Windows GPU presenting a video frame.
- An earlier [experimental Linux compile](https://github.com/Bntagaaa/BitChord-Desktop-Revived/actions/runs/44100963151) hit Maven Central HTTP 429 during dependency resolution. A later [experimental Windows run](https://github.com/Bntagaaa/BitChord-Desktop-Revived/actions/runs/44744527873) failed four AutoMix and loop-renderer tests. Those failures are separate from the startup black-screen issue.
- The experimental branch integrates MediaMP/libmpv only for the generic artist hero and music video. `cf1556cb` and `ba5d709f` add fit/crop and readiness handling, `48c33559` schedules redraw while warming, and `2b66687e` fixes a paused startup deadlock. The readiness helper queries estimated frame number or picture type. Both can advance while the visible surface is black. `hwdec=auto-safe` requests hardware decode without verifying it. The branch-wide fallback switch and separate player ownership leave per-session recovery and unified lifetimes unresolved.
