# BitChord Desktop Revived 1.8.3 — Performance & Memory Optimization Report

## 1. Overview & Objectives
This document summarizes the performance, startup, and memory optimizations introduced in release 1.8.3 for BitChord Desktop Revived.

Key goals achieved:
- **UI Responsiveness & Startup Time**: Window creation and initial UI frame render immediately without waiting for nonessential network, filesystem, or native model tasks.
- **Lazy Local Music Scanning**: Defer local folder scans and filesystem watcher registrations until Local Music or local music features are accessed.
- **Asynchronous & Cached Replay Summaries**: Replay stats calculations run off the main UI thread with in-memory caching and invalidation on data changes.
- **Progressive Home Loading & Background Verification**: Primary Home content renders as soon as available, while supplementary shelves and download verification run asynchronously.
- **Decoupled Library Initialization**: Account session restoration is decoupled from heavy multi-page Library fetching.
- **Adaptive Graphics & Performance Profiles**: Introduces `FULL`, `BALANCED`, `PERFORMANCE`, and `AUTO` rendering profiles with hardware-aware detection.
- **Tray & Minimized Idle Memory Trimming**: Trims image bitmap caches and triggers JVM garbage collection when the window is minimized or closed to the system tray.
- **Mandatory Invariant**: `Reduce dynamic blur` unconditionally overrides all dynamic blur effects across every UI surface.

## 2. Suspected Bottlenecks & Changes Implemented

### A. Startup Diagnostics (`DesktopStartupDiagnostics.kt`)
- Added monotonic `System.nanoTime()` instrumentation for milestone tracking.
- Opt-in via JVM system property `-Dbitchord.perf.diagnostics=true` or environment variable `BITCHORD_PERF_DIAGNOSTICS=1`.
- Tracks: `PROCESS_ENTRY`, `WINDOW_CREATED`, `FIRST_FRAME`, `ACCOUNT_RESTORED`, `LOCAL_MUSIC_SCAN`, `LOCAL_MUSIC_WATCHER`, `DOWNLOAD_VERIFY`, `HOME_FEED_REQUESTED`, `HOME_FEED_RENDERED`, `LIBRARY_LOADED`, and `ANALYSIS_RUNTIME_INIT`.
- Displays JVM Heap vs Process RSS without logging sensitive tokens/cookies.

### B. Startup Pipeline & Deferral (`Main.kt`, `DesktopApp.kt`)
- Moved native analyzer initialization (`DesktopAnalysisRuntime.ensureStarted()`) and download verification (`DesktopDownloadManager.verified()`) to background coroutines.
- Main window and Compose UI mount instantly on application entry.

### C. Lazy Local Music (`DesktopLocalMusic.kt`, `DesktopLocalMusicWatcher.kt`)
- Local Music filesystem scanning is deferred until the Local Music destination is opened or settings change.
- Uses `localMusicLoading` state indicator (`DesktopLoadingPage`) during first scan.
- File watcher registration is deferred until Local Music is loaded.

### D. Replay Statistics Optimization (`DesktopListeningStats.kt`)
- Replaced synchronous `DesktopListeningStats.summary()` call during initial composition with an empty default state.
- Added thread-safe in-memory caching in `DesktopListeningStats.summary(period)`.
- Updates run asynchronously on `Dispatchers.IO` when `statsRevision`, `replayPeriod`, or `activeAccountId` changes.

### E. Progressive Home Feed & Background Download Verification (`DesktopApp.kt`)
- Home feed loads progressively and logs `HOME_FEED_RENDERED` on first shelf publish.
- Added request-generation cancellation guards (`homeJob?.cancel()`) to prevent stale results.
- `DesktopDownloadManager.verified(downloads)` runs on `Dispatchers.IO` in background without holding back Home feed or startup UI.

### F. Decoupled Account & Library Initialization (`DesktopApp.kt`)
- `DesktopAccounts.activate()` restores user session independently.
- Heavy `DesktopSearchClient.library()` fetches (liked songs, added songs, user playlists) are triggered lazily when navigating to Library or opening playlist selection.

### G. Adaptive Graphics & Performance Profiles (`DesktopAppearanceSettings.kt`, `DesktopBlurCustomization.kt`)
- Introduced `DesktopPerformanceProfile` (`FULL`, `BALANCED`, `PERFORMANCE`, `AUTO`).
- `AUTO` mode uses logical CPU cores and available JVM memory (`detectHardwareProfile`).
- **Enforced Invariant**: `effectiveDesktopBlur(reduceDynamicBlur, selected, profile)` returns `false` if `reduceDynamicBlur` is `true` OR if `profile == PERFORMANCE`, ensuring 100% compliance across all UI components.

### H. Minimized & System Tray Memory Trimming (`DesktopMemoryOptimizer.kt`)
- Automatically clears decoded artwork bitmaps (`DesktopArtworkCache.clear()`), trims media file cache, and requests JVM Garbage Collection when the window is minimized or closed to the system tray (`onWindowHidden`).

## 4. Reproducible Performance Test Instructions

To enable performance diagnostics on Windows or Linux:

### Linux
```bash
export BITCHORD_PERF_DIAGNOSTICS=1
./gradlew :desktopApp:run
```

### Windows (PowerShell)
```powershell
$env:BITCHORD_PERF_DIAGNOSTICS="1"
.\gradlew.bat :desktopApp:run
```

### Windows (Command Prompt)
```cmd
set BITCHORD_PERF_DIAGNOSTICS=1
gradlew.bat :desktopApp:run
```

Diagnostic lines will appear in stdout and `DesktopTrackLog`:
```
[PERF_DIAGNOSTICS] [+120 ms] Process entry and bootstrap initialization | JVM Heap: 42MB / 512MB
[PERF_DIAGNOSTICS] [+310 ms] Window created | JVM Heap: 68MB / 512MB
[PERF_DIAGNOSTICS] [+325 ms] Account / session restored - Signed in: true | JVM Heap: 72MB / 512MB
[PERF_DIAGNOSTICS] [+450 ms] Home feed request started | JVM Heap: 78MB / 512MB
[PERF_DIAGNOSTICS] [+780 ms] Home feed first content rendered | JVM Heap: 95MB / 512MB
```
