# BitChord Desktop Reworked feature coverage

Baseline: original BitChord stable `v1.9.1`, commit `7f45c768a461fd7e68bf4613f71e8a767e643d4c`. Additional desktop behavior was audited against Revived branch `1.9.2`, commit `1e65021e7c05b8692afb7e35cd5cfff52035f4b0`.

This is a mobile-derived Windows/Linux target. It does not reuse historical desktop or web implementations. [REWORKED_PROVENANCE.md](REWORKED_PROVENANCE.md) identifies direct original-mobile ports and newly written boundaries.

## Reading the status

**Implemented** means there is a functional code path and a user-facing entry point. It does not imply successful external-account authentication, hardware testing, or an installer smoke test. **Automated** refers only to tests recorded in the verification section. **Platform verification required** identifies an operating-system behavior that cannot be established by a Linux compiler or a unit fixture. **Gap** means behavior remains absent or differs materially; an enabled no-op control is not considered an implementation.

Unless shown otherwise, new port files below are in `desktopApp/src/main/kotlin/com/music/bitchord/reworked/`. Mobile paths are relative to original `app/src/main/java/com/music/bitchord/`; `shared/` and `sharedUi/` refer to their original modules.

## Explicit gaps and applicability boundaries

These are not silently represented as working controls:

| Boundary | Current state |
| --- | --- |
| Android hardware-attested addon verification | Cannot be reproduced with a desktop token. Addons requesting it are shown unavailable with the reason. The port does not impersonate a verified Android device. |
| Verified lossless physical output / exclusive USB DAC / Dolby Atmos pass-through | Java Sound shared output cannot assert the mobile device verification contract. Addons requiring verified lossless output are withheld; Atmos responses after a stereo request are rejected. EQ/widening are not advertised as Atmos. |
| Wear OS, Android Auto/TV, Android Media3 services, Android USB permission/AAudio plumbing | Android-only hosts remain Android features. Desktop equivalents are the new window/queue/audio output/media-control adapters, not those Android components. |
| Background sync while the desktop process is closed | The mobile Android WorkManager scheduler has no background desktop service here. Downloaded-playlist sync resumes on launch and runs while Reworked is open. |
| Connection type and metered-download detection | The desktop host exposes one active streaming profile and an independent download profile. Android cellular/Wi-Fi, battery and WorkManager network constraints are not asserted on an unidentified desktop network. |
| Revived profile migration | Deliberately separate data. There is no automatic import of old settings, passwords or playlists. An explicit migration utility would be additional work. |
| Full Windows/Linux service/device verification | Compiler success and fixture tests cannot verify OAuth, a physical audio device, SMB server, Windows media controls, or real packaged updates. These require the stated smoke tests. |

The concrete non-optimization 1.9.2 items still requiring final comparison are exact historic artist/detail/card presentation, full video switch/fullscreen layout behavior, and the Windows/native-update paths. Their new implementations are listed above; they must not be described as visually or operationally identical without those checks.

## Release identity

New builds use the `BitChordReworked` product and `reworked-v…` release tags. The ordinary `-reworked.<number>` product revision is accepted on the stable update channel when GitHub marks the release as non-prerelease. Alpha/beta/RC versions and explicitly prerelease-marked releases remain behind the preview option. SHA-256, size and exact asset/product namespace are checked independently of channel selection.

Native package versions preserve the Reworked revision numerically: `1.9.1-reworked.1` maps to `1.9.1001`. Full runtime versions and update tags/assets keep `1.9.1-reworked.1`; see [build and release instructions](REWORKED_BUILD.md).
