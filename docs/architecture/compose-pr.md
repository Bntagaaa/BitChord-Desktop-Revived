Desktop presentation was compiled through the Android/JVM UI target, while thumbnail loads had no shared request ownership, could decode the same image for several screens concurrently, and could refill a cleared cache. This experiment creates a JVM-only `desktopUi` target and an Android/Compose-free `desktopRuntime` module for byte budgets, shared loads and application resource ownership. Existing layouts/assets are reused, and renderer versions remain pinned to the existing Windows/Linux combinations.

Application-owned artwork loads share one producer per URL, cap concurrent decoding, respect the cache budget even for oversized images, and invalidate old cache generations without abandoning visible readers. Presence subscriptions and artwork work have an explicit shutdown owner. Presentation collectors follow native window visibility independently of background playback; disk trimming and the existing hidden-window GC policy run outside the UI thread and coalesce duplicate hide callbacks.

Validation so far: desktop module configuration/resource generation and runtime ownership/cancellation tests pass locally. Full Windows/Linux/Android builds and real desktop render tests run in this branch's CI. Packaged-process before/after memory measurements, broader domain/navigation extraction, optional service/native lifetime audits, and live integration/visual parity verification are still pending. No 30% memory reduction or complete re-architecture is claimed.
