Desktop presentation was compiled through the Android/JVM UI target, while thumbnail loads had no shared request ownership, could decode the same image for several screens concurrently, and could refill a cleared cache. This experiment creates a JVM-only `desktopUi` target and an Android/Compose-free `desktopRuntime` module for byte budgets, shared loads and application resource ownership. Existing layouts/assets are reused, and renderer versions remain pinned to the existing Windows/Linux combinations.

Application-owned artwork loads share one producer per URL, cap concurrent decoding, respect the cache budget even for oversized images, and invalidate old cache generations without abandoning visible readers. Presence subscriptions and artwork work have an explicit shutdown owner. Presentation collectors follow native window visibility independently of background playback; disk trimming and the existing hidden-window GC policy run outside the UI thread and coalesce duplicate hide callbacks.

Addon Graal contexts also share one serialized owner per module key. Reload cannot leak a late context or close a native handle under its current call, and failed initialization disposes its context.

Playback clock ticks no longer invalidate the whole desktop presentation. Playhead/video consumers keep the original clock samples, platform integrations read the engine snapshot, and transport/metadata changes remain observable. A Compose test checks scrubber updates independently of application recomposition.

Validation so far: 15 runtime ownership/cancellation tests in `:desktopRuntime`, presentation-lifetime and regression tests in `:desktopUi`, and playback clock isolation tests in `:desktopApp` pass locally with JDK 21. CI verification is complete across all platforms: at commit 64d7e70a, branch CI run 42547639362 passed Linux and Windows tests, Android and Go backend checks, AppImage packaging, and generated complete Windows portable ZIP, EXE, and MSI installers. In addition, Compose visual parity run 42547190826 passed on both Windows and Linux with 100% pixel-by-pixel equality across all 18 test fixtures. Pinned packaged idle benchmarks (runs 42546036077 and 42547573281) recorded process PSS/RSS, heap, JVM NMT committed bytes, thread CPU attribution, and native library inventories. Full playback/navigation/long-session measurements, broader domain/navigation extraction, and live authenticated integration checks remain pending. No 30% memory reduction or complete re-architecture is claimed.
